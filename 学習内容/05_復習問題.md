# 05. 今回のコマンド復習問題（初級〜中級）

次の問題は、**何のためにそのコマンドを使うか**を思い出す練習です。答えを見ずに、言葉で説明してみよう。

## 問題

1. Windows踏み台から物理Ubuntu Serverへ安全にログインするコマンドは？ `<SERVER_IP>` には何を入れる？
2. `pwd` と `ls` の違いは？
3. `cd ~/first-app` の `~` は何を意味する？
4. `sudo` は何のために付ける？
5. `git clone` と `git pull` の違いは？
6. `mvn clean package` で `clean` と `package` は何をしている？
7. `java -D... -jar ... --server.port=8081` で `-D` はなぜ `-jar` の前に書く？
8. `127.0.0.1` は何のIP？踏み台側とUbuntu側で同じコンピューターを指す？
9. `curl -I http://127.0.0.1:8081/` で `HTTP/1.1 200` が出たら何が確認できる？
10. `ps -ef | grep '[j]ava'` の `|` は何をする？
11. `kill 28872` を次回もそのまま実行してはいけない理由は？
12. `ssh -N -L 127.0.0.1:18081:127.0.0.1:8081 ...` は何を中継している？
13. SSHトンネル用PowerShellを閉じたらsystemdのアプリも止まる？
14. `sudo nano ...` で編集したファイルを保存するキー操作は？
15. `systemctl daemon-reload` と `systemctl restart myfirstapp` の違いは？
16. `active (running)` と `enabled` はそれぞれ何を意味する？
17. `sudo systemctl stop myfirstapp` と `sudo shutdown -h now` は何が違う？
18. 自動起動の設定を検査するコマンドは？
19. `myfirstapp` というログインできない専用ユーザーを作った理由は？
20. GitHubに載せてはいけない接続情報は何？

---

## 解答・解説

1. `ssh kazuha@<SERVER_IP>`。接続先は管理者から割り当てられた**Ubuntu OS側のIP**に置き換える。初回のホスト鍵は照合する。
2. `pwd` は**現在いる場所のパスを表示**、`ls` は**その場所のファイル一覧を表示**。
3. `~` は自分のホームディレクトリ。今回の例なら `/home/kazuha`。
4. 管理者権限が必要なファイル作成やシステム設定変更を行うため。誤用するとシステムを壊せるので注意。
5. `clone` はリポジトリを最初に複製、`pull` は既存の作業ディレクトリに更新を取り込む。
6. `clean` は過去の `target/` のビルド生成物を削除、`package` はコンパイル・テストを行いJARを作る。
7. `-D` は**JVM自体に渡す設定**だから。`--server.port` はSpring Bootアプリに渡すのでJAR名より後。
8. `127.0.0.1` はそのPC自身を指す。踏み台でのlocalhostとUbuntuでのlocalhostは**別の場所**。
9. そのリクエストについてWebサーバーが正常なHTTP応答を返したこと。アプリの全機能・OS全体の健全性は保証されない。
10. 左コマンドの出力を右コマンドに渡す。ここでは `ps` の一覧からJavaに関係する行を `grep` で絞っている。
11. PIDは再起動や時間経過で変更・再利用されるから。**毎回対象を確認**しないと別のプロセスを止める危険がある。
12. **踏み台の127.0.0.1:18081**に来た通信をSSH経由で**Ubuntuの127.0.0.1:8081**へ転送する。
13. 止まらない。トンネルだけが終了してブラウザ接続が切れる。systemdのサービスは別に管理される。
14. `Ctrl+O` → `Enter` → `Ctrl+X`。
15. `daemon-reload` はsystemdの**設定読み直し**、`restart` はアプリの**実際の停止と起動**。前者だけでは動作中のJavaは置き換わらない。
16. `active (running)` は**現在動作中**、`enabled` は**次回のOS起動時に起動する登録が有効**。
17. `stop` はアプリだけを停止、`shutdown` はUbuntuのOS全体を停止する。
18. `systemctl is-enabled myfirstapp`。今回の共有ログでは `enabled` 結果はまだ未確認。
19. Javaアプリに普段のログインユーザーの権限を与えず、侵害時の被害範囲を減らすため。
20. パスワード、秘密鍵、アクセストークン、非公開の管理画面URLや内部ネットワーク情報など。公開リポジトリには載せない。

## 自分で確認する練習

UbuntuのSSHターミナルで、読み取り中心のコマンドだけを順番に実行して、結果を説明してみよう。

```bash
pwd
ls -lh /opt/myfirstapp/
readlink -f "$(command -v java)"
ps -ef | grep '[j]ava'
systemctl status myfirstapp --no-pager
systemctl is-enabled myfirstapp
curl http://127.0.0.1:8081/api/monitor/health
```

これらは通常、サーバーの設定を変更しない。結果を誰かに共有するときは接続情報・ユーザー名などの公開範囲に注意する。
